# InkLoom Developer Skill Guide

This guide is designed for all AI Agents working on the **InkLoom** repository. It contains specifications, UI design systems, custom component mappings, and routing conventions. Please read this guide before making edits to layout, styles, or content pages.

---

## 📂 Project Structure & Routing

InkLoom is built on **Astro Starlight**. Pages are written in MDX.
- **Content Folder**: `src/content/docs/`
- **Sidebar Integration**: The sidebar is auto-generated by the `starlight-auto-sidebar` plugin. Directory labels and ordering are declared using `_meta.yml` files (e.g. `src/content/docs/objective/criminal/23/_meta.yml`).
- **Base Routing**: The project has `base: '/inkloom'` in its config.
  > [!IMPORTANT]
  > When writing links in MDX or Astro components, **always prepend the base path `/inkloom/`** (e.g. `/inkloom/objective/criminal/23/joint-crime/`). Do not use bare absolute paths like `/objective/...` as they will result in a 404 on GitHub Pages.

## 🎨 Custom Design Systems & Components

InkLoom provides custom-coded components (imported inside MDX files) to create premium interactive flowcharts for law cases.

### 1. Tag & Metadata badges
- `<TagGroup>`: Horizontal flex wrapper for metadata.
- `<Badge variant="...">`: Renders Starlight-aligned pill tags.
- `<MoneyBadge amount="...">`: Renders green currency tags for case transaction tracking.

### 2. Main Structure Components
- `<CaseCard title="..." subject="..." year="...">`: Highlight box outlining the factual background.
- `<ModelCard title="..." subtitle="..." type="...">`: Wraps a single legal scenario/model. Contains `<VisualFlow>` and `<ModelAnalysis>`.

### 3. Interactive Diagrams & Highlighting
- `<VisualFlow amountA="..." action="..." relationInfo="...">`: Connects Briber ➔ Intermediary ➔ Recipient with flow lines.
- `<ModelAnalysis>`: A 3-column flex container.
- `<ActorColumn actor="..." title="...">`: Renders a vertical column for **甲**, **乙**, or **丙**.
- `<ActionBlock class="..." icon="..." label="..." money="..." badge="...">`: Action step capsule.
  - Adding `class="trigger-link-1"` or `class="trigger-link-2"` establishes hover highlights. When hovered, the corresponding paths in `<VisualFlow>` will animate faster and light up.
- `<ConclusionBlock type="..." label="...">`: Final legal conclusion for that actor in this model.

### 4. Interactive Matrix & Recall
- `<ComparisonBoard>` and `<ComparisonRail>`: Used to build responsive comparison matrices comparing models.
- `<details class="interactive-card">`: Collapsible flashcards for self-testing.

## 🧠 Memory Challenge Mode (消隐背诵模式)

InkLoom integrates a checkbox-toggle-based memory masking system:
- **Checkbox Element**: `<input type="checkbox" id="memory-challenge-toggle" style="display: none;" />` is defined at the top of the MDX content.
- **Content Wrapper**: The entire note body is wrapped in `<div class="note-content-wrapper">`.
- **Blur Effect**: When the checkbox is active, key elements with the `.answer-node` class are blurred (`filter: blur(5px)`). Hovering over a blurred block temporarily reveals the text.
- **Obsidian Compatibility**: Because this uses CSS sibling selection (`#memory-challenge-toggle:checked ~ .note-content-wrapper`), the interactive blur works natively in Notion and Obsidian copy-pastes without requiring Javascript!

## 🎛️ PageTitle Overrides & Layout Hacks

Starlight's layout is overridden using custom styling and scripts in `src/components/overrides/PageTitle.astro`:

1. **Floating Tick TOC (液态玻璃大纲)**:
   - Built inside `PageTitle.astro`. Replaces the native right sidebar on small screens and desktop.
   - Designed with 3D spherical liquid glass reflections (layered inset shadows) and no frosted blur.
   - When collapsed, it shows a grey tick strip. When hovered, it expands into a text outline list.
   - Toggles text visibility explicitly using `display: none` / `display: inline-block` to avoid flexbox width bugs.
2. **Quick Actions Toolbar**:
   - A sleek capsule toolbar in the top-right corner of the page title.
   - Contains Copy HTML (clones content and appends inline CSS styles), Copy Iframe (injects a dynamic `?t=Date.now()` cache-buster to bypass Obsidian webview cache), and the Memory Toggle brain button.
3. **Widescreen Layout Override**:
   - By default, Starlight reserves 300px for a right sidebar. In `src/styles/custom.css`, we override this under `@media (min-width: 72rem)`:
     ```css
     .main-pane { grid-template-columns: 1fr !important; }
     .content-panel, .sl-container, .sl-markdown-content, main { width: 100% !important; max-width: none !important; margin-inline: 0 !important; }
     ```

## 📝 Conversion Guidelines (Note Markdown to MDX)

When importing raw notes from `notes/` into `src/content/docs/objective/`:

1. **Distinguish Native Note Tables vs. Hand-written Custom HTML**:
   - **Native Tables**: Note apps (like Siyuan Note) store standard tables using HTML `<table>` elements. These are **not** hand-written HTML. Leave them as simple `<table>` elements (if using `rowspan`/`colspan`) or convert them to standard Markdown tables. Do not over-engineer them.
   - **Hand-written Custom HTML**: Look for custom styled blocks with inline CSS layouts (e.g., `display: flex`, `flex: 1`, custom borders, box-shadows, colors, such as the `⚡ 电力案核心区分` boxes). These are hand-written structures that should be converted to clean, modern MDX elements or Starlight grids/cards.
2. **Relative Asset Resolving**:
   - Copy any referenced images from the notes `assets/` folder to the target directory's `assets/` subfolder.
   - Update image paths in MDX to relative `./assets/...` syntax so that Astro's image optimizer can build them.
